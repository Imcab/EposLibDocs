    Configuration fields#

    Every field of every configuration group, with the object it is written to and the comment from the source. All fields are std::optional: only the ones that are set are written by Apply(), and Refresh() fills every one it can read. Fields marked read-only are filled by Refresh() and never written.

    See Configuration for how to use them.

    CyclicConfigs#

    Field Type Object Notes
    interpolationTimePeriodMs std::uint8_t od::cia402::kInterpolationTimePeriod_InterpolationTimePeriodValue 0x60C2:01, [ms], 0 to 100. MUST match the master's synchronised PDO cycle - the SYNC period in the network description. With bus.yml at sync_period: 10000 (microseconds), this is 10. The manual on leaving it at 0: the drive "immediately takes the new set value and adapts the position [...] within the next control cycle (i.e. 0.4 ms). Afterwards it holds this set value until the next set value of the master is received. This results in an interrupted and noisy motion if the master just provides new set values at cycle rates of 1 ms, 2 ms, or even lower." In other words: a joint that steps instead of moving. Set it wrong in the other direction - larger than the real cycle - and the drive interpolates over a window that never completes, which lags the commanded trajectory.

    StandstillConfigs#

    Field Type Object Notes
    window std::uint32_t od::maxon::kStandstillWindowConfiguration_StandstillWindow 0x30E0:01 [velocity units], default 30. Symmetric band around zero. The value 0xFFFFFFFF switches standstill detection off entirely and standstill is deemed reached at the end of the trajectory - which is exactly the assumption that damages a brake on an axis still coasting.

    windowTimeoutMs std::uint16_t od::maxon::kStandstillWindowConfiguration_StandstillWindowTimeout 0x30E0:03 [ms]. Give up waiting for standstill after this long.
